# 常见问题（FAQ）

> 安装和使用「任务中转站」过程中的常见问题。

---

## 安装相关

### Q：必须用 Obsidian 吗？

**A：** 不必须。中转层可以放在任何本地文件夹，Obsidian 只是**最方便**的查看/编辑工具。

如果你不用 Obsidian：
- VSCode + Markdown 插件
- Typora / MarkText
- 任何文本编辑器

### Q：必须用 Git 同步中转层吗？

**A：** 不必须，但**强烈推荐**。同步方案：

| 方案 | 适用 |
|------|------|
| Git + GitHub | 跨机器、跨平台 |
| OneDrive / iCloud | 个人多设备 |
| 坚果云 | 国内访问快 |
| 都不用 | 单机器本地使用 |

### Q：TRANSIT_ROOT 路径里能用中文吗？

**A：** 能。Windows / macOS / Linux 都支持中文路径。

但**避坑**：
- 路径里不要有空格（容易踩坑）
- 避免特殊字符 `&`、`|`、`#`
- 移动路径时用绝对路径，**不要用快捷方式**

### Q：能装在云端吗（比如公司共享盘）？

**A：** 不建议。中转层需要**文件锁**逻辑，云盘同步可能导致冲突。推荐：

- 个人本地 + Git 同步
- 或者每个 agent 各自本地 + 共享中转层（用 Git pull/push 同步）

## 配置相关

### Q：配置写错了怎么办？

**A：** 改 `~/.zhongzhuan-task/config.json` 对应字段，然后对 agent 说"重新加载配置"或重启 agent。

### Q：能让多个 agent 共享一个配置吗？

**A：** 不能，配置是 agent 本地的。但**所有 agent 共享同一个 `TRANSIT_ROOT`**，这是设计的协作点。

### Q：CLAIM_TIMEOUT_HOURS 怎么选？

**A：** 看协作密度：

| 场景 | 建议值 |
|------|--------|
| 实时多 agent 协作（同时在线）| 4-6 小时 |
| 时差大、跨日工作 | 24-48 小时 |
| 偶尔协作 | 48-72 小时 |

### Q：AGENT_ID 命名规范？

**A：** 推荐格式 `<平台>-<昵称>`：

```
✅ codeBuddy-阿宝
✅ cursor-本地
✅ claude-code
✅ chatgpt-gpt4
❌ agent1         # 不够独特
❌ 2026-08-20     # 不是名字
```

## 使用相关

### Q：claim 一个任务后多久没做完会被接管？

**A：** 超过 `CLAIM_TIMEOUT_HOURS`（默认 24h）就算。但**强烈建议**：

- 长任务：执行过程中在任务文件写进度更新（修改 `updated` 字段），证明还在做
- 进度更新也算"更新"，会重置超时计时

### Q：怎么知道中转层有什么任务？

**A：** 对 agent 说：

```
看下中转层有什么任务
```

或直接读 `当前关注.md`。

### Q：任务做错了能撤销吗？

**A：** 可以：

```
取消中转任务：xxx
```

agent 会把 status 改为 `cancelled`，并在文件里写取消原因。

### Q：能"分阶段"做任务吗？

**A：** 能。3 种方式：

1. **拆成多个子任务**（推荐）：粒度更细，状态清晰
2. **claim 后多次更新 `updated` 字段**（防超时），最后 status 改 done
3. **先改 status 为 blocked**，写明暂停原因

### Q：怎么避免重复创建同名任务？

**A：** 制定任务前 agent 会先 `ls code/active/` 检查同名文件。如有，询问你"是更新还是新建"。

## 平台相关

### Q：WorkBuddy 找不到我的中转层？

**A：** 检查：

1. `~/.zhongzhuan-task/config.json` 是否存在且格式正确
2. `TRANSIT_ROOT` 路径用双反斜杠（Windows）：`"D:\\文档\\中转层"`
3. 路径在系统中真实存在

### Q：Cursor 不自动 claim 任务？

**A：** Cursor 对工具调用的支持不如 WorkBuddy 自动。可能需要：

1. 在 Chat 中明确说："请读取任务文件，claim 后开始执行"
2. 手动触发工具调用（Cursor Composer 需 @Files）

### Q：ChatGPT 怎么用？

**A：** ChatGPT 无文件访问能力。**变通方案**：

1. 复制 `当前关注.md` 全文粘给 ChatGPT
2. 让它生成新任务文件 Markdown 内容
3. 你手动保存到中转层

### Q：协议升级会破坏老任务吗？

**A：** 不会。协议升级遵循：

- 新字段添加，老 agent 忽略即可
- 旧字段保留，新 agent 兼容读
- 状态机不变

## 协作相关

### Q：多 agent 同时 claim 不同任务会有问题吗？

**A：** 不会。锁是**任务级**的，不同任务互不干扰。

### Q：A agent 看到 B agent 在做，临时加入帮忙可以吗？

**A：** 不建议。会导致状态混乱。如果要合作：

1. 拆成两个子任务
2. 或等 B agent 完成后再修改

### Q：客户想看任务进度怎么分享？

**A：** 几种方式：

1. 直接分享 `当前关注.md` 给他看
2. 截图索引页
3. 用 Obsidian Publish 把 vault 公开
4. 每周邮件发周报（自动化的可以做）

### Q：能用 ChatGPT 规划，Cursor 执行吗？

**A：** 完全可以，这是本协议的典型场景。流程：

1. ChatGPT 规划 → 输出任务 Markdown
2. 你手动保存到中转层
3. Cursor 读任务 → claim → 执行
4. Cursor 写执行结果

## 故障排查

### Q：任务状态错乱怎么办？

**A：** 手动检查 frontmatter：

1. 打开任务文件
2. 检查 `status`、`claimed_by`、`claimed_at`
3. 如有冲突，手动改为正确状态
4. 同步更新 `当前关注.md`

### Q：agent 写错了文件怎么办？

**A：** 任务文件在 Git 管理下：

```bash
git log 任务文件.md      # 看历史
git checkout HEAD~1 -- 任务文件.md  # 回退到上一版
```

### Q：中转层变得很乱怎么整理？

**A：**

1. 归档已完成任务到 `archive/YYYY-WW/`
2. 删除被取消的 cancelled 任务
3. 合并重复任务
4. 重新组织 `当前关注.md`
