# 跨平台兼容

「任务中转站」设计为一个**纯文本协议**（纯 Markdown + JSON 配置文件），理论上任何能读写本地文件的工具都能参与。本文档文档详细列出已验证的适配方法。

---

## 平台支持总览

| 平台 | 触发方式 | 配置位置 | 限制 |
|------|---------|---------|------|
| **WorkBuddy** | 触发词生效 | `~/.workbuddy/skills/` | 无 |
| **Cursor** | `.cursorrules` 自动生效 | 项目级 `.cursorrules` | 单项目 |
| **Claude Code** | Skill 自动加载 | `~/.claude/skills/` | 无 |
| **ChatGPT** | 自定义指令 | 设置面板 | 每次会话需说明 |
| **通用 agent** | system prompt | 任意 | 取决于 agent 能力 |

---

## WorkBuddy

**最完整支持。** 通过 skill 触发词，agent 自动执行完整工作流。

### 安装

```bash
# 把整个仓库复制到 skills 目录
cp -r agent-collab-task ~/.workbuddy/skills/zhongzhuan-task
```

### 触发词

- "制定中转任务：xxx"
- "执行中转任务"
- "看下中转层有什么任务"
- "配置中转任务路径"

### 优势

- ✅ 自动文件读写（`Read/Write/Edit`）
- ✅ 触发词自动识别
- ✅ AskUserQuestion 引导首次配置
- ✅ 与 WorkBuddy 其他 skill 协同

### 限制

- 无（WorkBuddy 全功能）

## Cursor

Cursor 读 `.cursorrules` 文件作为 system prompt 的一部分。

### 安装

在项目根目录创建 `.cursorrules`，追加：

```markdown
# === 任务中转站协议 ===

<把 SKILL.md 的"工作流"章节完整粘贴>

# TRANSIT_ROOT 设置
我的中转层路径：D:\文档\中转层
我的 agent ID：cursor-本地

# === 协议结束 ===
```

### 触发方式

在 Cursor Chat 中说：

- "制定中转任务：xxx"
- "执行中转任务"

### 优势

- ✅ 与 Cursor Composer 无缝集成
- ✅ 单项目可定制

### 限制

- ⚠️ `.cursorrules` 是项目级，**每个项目需单独配置**（除非用全局 Cursor 设置）
- ⚠️ Cursor 对 frontmatter 的 `Write/Edit` 操作需要手动触发工具调用

## Claude Code

Claude Code 支持自定义 skill，存放在 `~/.claude/skills/`。

### 安装

```bash
mkdir -p ~/.claude/skills/zhongzhuan-task
cp -r agent-collab-task/* ~/.claude/skills/zhongzhuan-task/
```

### 触发方式

Claude Code 自动检测 `SKILL.md`，触发词生效：

- "请帮我制定中转任务"
- "执行中转任务"

### 优势

- ✅ Claude Code 文件读写能力强
- ✅ 支持 Bash 命令（可以 `mkdir -p`）
- ✅ 工具调用丰富

### 限制

- ⚠️ 需要 Claude Code 订阅

## ChatGPT

ChatGPT 没有文件系统访问权限，但可以**人工**把中转层内容贴进对话。

### 安装（替代方案）

在 ChatGPT 设置 → 自定义指令，粘贴：

**"How would you like ChatGPT to respond?"** 部分：

```
你是一个任务协作 agent，使用「任务中转站」协议。
当我说"制定中转任务：xxx"时，你输出任务文件 Markdown 内容给我，让我手动创建。
当我说"执行中转任务"时，我贴任务文件内容给你，你按工作流执行。
详细协议见：https://github.com/cityhonter/agent-collab-task/blob/main/SKILL.md
```

**"What would you like ChatGPT to know about you?"** 部分：

```
我使用「任务中转站」协议。中转层在我的 D:\文档\中转层。
agent ID：chatgpt-gpt4
```

### 触发方式

- "制定中转任务：xxx" → ChatGPT 输出 Markdown 内容
- "执行中转任务" + 贴任务文件 → ChatGPT 按工作流推演

### 优势

- ✅ 不需本地环境
- ✅ 任何有 ChatGPT 账号的人都能用

### 限制

- ❌ **无文件读写能力**，需要手动复制粘贴
- ⚠️ 每次会话都需重新告知上下文
- ⚠️ 不适合需要写大量文件的场景

## 通用 agent

任何能读 Markdown 文件的工具都可适配。

### 最小可用配置

把以下内容加入 agent 的 system prompt：

```
# 协议：任务中转站

你是一个任务协作 agent。中转层路径：{TRANSIT_ROOT}

## 角色：制定者

触发词："制定中转任务：xxx"
工作流：
1. 读 {TRANSIT_ROOT}/当前关注.md
2. 创建 {TRANSIT_ROOT}/code/active/{标题}.md 或 other/active/{标题}.md
3. 更新 {TRANSIT_ROOT}/当前关注.md

## 角色：执行者

触发词："执行中转任务"
工作流：
1. 读 {TRANSIT_ROOT}/当前关注.md
2. 检查锁（claimed_by）
3. claim → 执行 → 回报

完整协议：https://github.com/cityhonter/agent-collab-task
```

## 多 agent 协作实战

最实用的场景：**WorkBuddy 规划 + Cursor 执行**

```
[WorkBuddy]                     [Cursor IDE]
    │                                │
    ├─ "制定中转任务：实现登录" ──────>│
    │   (写入中转层任务文件)            │
    │                                │
    │<───────────── git pull ─────────┤
    │                                ├─ 读任务文件
    │                                ├─ claim 上锁
    │                                ├─ 写代码、跑测试
    │                                ├─ 回报 result
    │                                │
    │<───────────── git pull ─────────┤
    ├─ 看到 done 状态                  │
    └─ 验收结果                       │
```

### 同步方案

| 方案 | 适用 |
|------|------|
| **Git** | 跨机器、技术能力强 |
| **OneDrive / iCloud** | 跨设备自动同步、简单 |
| **坚果云** | 国内同步、速度好 |

## 协议版本兼容

所有平台都遵循同一份 SKILL.md，**协议升级是平滑的**：

- 老任务文件始终可读（新字段可忽略）
- 新功能通过新增 frontmatter 字段实现，不破坏旧字段
- 平台支持差异见 [docs/常见问题.md](常见问题.md)
