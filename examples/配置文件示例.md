# 配置文件示例

> 不同平台、不同场景的 `config.json` 完整示例。

---

## 1. 最小配置（Windows + WorkBuddy）

```json
{
  "TRANSIT_ROOT": "D:\\文档\\workSpace\\中转层",
  "AGENT_ID": "codeBuddy-阿宝"
}
```

只填必填项，其他用默认值（CLAIM_TIMEOUT_HOURS=24）。

---

## 2. 完整配置（Windows + WorkBuddy）

```json
{
  "TRANSIT_ROOT": "D:\\文档\\workSpace\\中转层",
  "VAULT_NAME": "workSpace",
  "CLAIM_TIMEOUT_HOURS": 24,
  "AGENT_ID": "codeBuddy-阿宝"
}
```

关联 Obsidian vault 时填 `VAULT_NAME`。

---

## 3. macOS + Claude Code

```json
{
  "TRANSIT_ROOT": "/Users/cityhonter/Documents/中转层",
  "CLAIM_TIMEOUT_HOURS": 12,
  "AGENT_ID": "claude-code"
}
```

超时设短一点（12h）—— Claude Code 通常执行快，响应及时。

---

## 4. Linux + Cursor（项目级）

Cursor 没有全局配置，**每个项目**单独配。

在项目根目录的 `.cursorrules` 中加：

```
# 任务中转站协议配置
我的中转层路径：/home/cityhonter/Documents/中转层
我的 agent ID：cursor-本地
```

---

## 5. 时差协作配置

如果你的协作 agent 在不同时区（如海外 Freelancer），超时设长一点：

```json
{
  "TRANSIT_ROOT": "/Users/cityhonter/Documents/中转层",
  "CLAIM_TIMEOUT_HOURS": 72,
  "AGENT_ID": "codeBuddy-阿宝"
}
```

---

## 6. 多 vault（中转层在多个 vault 共享）

如果你有多个 Obsidian vault，但中转层用同一份：

```json
{
  "TRANSIT_ROOT": "/Users/cityhonter/Documents/中转层",
  "VAULT_NAME": "primary",
  "CLAIM_TIMEOUT_HOURS": 24,
  "AGENT_ID": "codeBuddy-阿宝"
}
```

> 中转层**可以独立于 vault**，放在任何文件夹。`VAULT_NAME` 只是让 agent 知道关联的 Obsidian 编辑器打开哪个 vault。

---

## 7. 同一机器多 agent 区分

在一台机器上同时用 WorkBuddy + Cursor + Claude Code，AGENT_ID 必须互不相同：

**WorkBuddy 配置：**

```json
{
  "TRANSIT_ROOT": "D:\\文档\\中转层",
  "AGENT_ID": "codeBuddy-阿宝"
}
```

**Cursor `.cursorrules`：**

```
我的 agent ID：cursor-本地
```

**Claude Code 配置：**

```json
{
  "TRANSIT_ROOT": "D:\\文档\\中转层",
  "AGENT_ID": "claude-code"
}
```

---

## 8. 用 OneDrive 同步中转层（跨设备）

把中转层放在 OneDrive 同步目录：

```json
{
  "TRANSIT_ROOT": "C:\\Users\\cityhonter\\OneDrive\\Documents\\中转层",
  "AGENT_ID": "codeBuddy-阿宝-笔记本"
}
```

⚠️ **注意：** OneDrive 同步可能导致文件锁冲突。**不推荐**用 OneDrive 同步 active/ 目录（agent 正在修改），但 **done/ 和 archive/ 是只读的**，可以同步。

---

## 9. 团队共享中转层（用 Git）

团队成员各自本地，但中转层用 Git 同步到共享仓库：

**A 同事（Mac）：**

```json
{
  "TRANSIT_ROOT": "/Users/A/Documents/中转层",
  "AGENT_ID": "A-codeBuddy"
}
```

**B 同事（Windows）：**

```json
{
  "TRANSIT_ROOT": "D:\\Users\\B\\Documents\\中转层",
  "AGENT_ID": "B-cursor"
}
```

`TRANSIT_ROOT` 路径可以不同，但都用 Git 同步到同一仓库。

⚠️ **强烈建议**用 **branch 隔离**（每人一个分支），避免 `当前关注.md` 冲突。

---

## 10. 临时调试（用一个 throwaway 配置）

调试时不想影响主配置，可以临时覆盖：

**Windows PowerShell：**

```powershell
$env:ZHONGZHUAN_CONFIG = "C:\temp\debug-config.json"
# 启动 agent
```

（agent 需要支持环境变量配置读取）

## 快速生成脚本

### Windows PowerShell

```powershell
$config = @{
  TRANSIT_ROOT = "D:\文档\workSpace\中转层"
  VAULT_NAME = "workSpace"
  CLAIM_TIMEOUT_HOURS = 24
  AGENT_ID = "codeBuddy-阿宝"
}

New-Item -ItemType Directory -Force -Path "$HOME\.zhongzhuan-task"
$config | ConvertTo-Json | Out-File -Encoding utf8 "$HOME\.zhongzhuan-task\config.json"

Write-Host "配置已生成：$HOME\.zhongzhuan-task\config.json"
Get-Content "$HOME\.zhongzhuan-task\config.json"
```

### macOS / Linux Bash

```bash
mkdir -p ~/.zhongzhuan-task
cat > ~/.zhongzhuan-task/config.json << 'EOF'
{
  "TRANSIT_ROOT": "/Users/cityhonter/Documents/中转层",
  "VAULT_NAME": "workSpace",
  "CLAIM_TIMEOUT_HOURS": 24,
  "AGENT_ID": "codeBuddy-阿宝"
}
EOF
cat ~/.zhongzhuan-task/config.json
```

## 验证配置

```bash
# 文件存在性
ls ~/.zhongzhuan-task/config.json

# JSON 格式验证
# macOS/Linux:
python3 -c "import json; print(json.load(open('$HOME/.zhongzhuan-task/config.json')))"
# Windows PowerShell:
Get-Content $HOME\.zhongzhuan-task\config.json | ConvertFrom-Json

# 中转层存在性
ls <TRANSIT_ROOT>
```
